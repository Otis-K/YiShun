## 2. 闭环状态机

每一个功能和验收用例只能按以下状态推进：

```text
not-run -> running -> failed -> fixed -> rerun -> passed
                         \-> blocked-with-evidence
```

禁止从 `failed`、`not-run` 或 `blocked-with-evidence` 直接进入 `passed`。每次修复后必须更新源码指纹并重跑受影响级别及所有回归级别。

## 3. 阶段与退出条件

### A. 证据与门禁修复

- 初始化可用的本地 Git 元数据或生成等价、稳定的源码清单与 SHA-256 指纹。
- 报告聚合器读取真实 L0-L5 报告，不允许写死通过数或状态。
- Manifest 的 684 个用例状态由报告映射更新。
- 性能预算、超时、取消、原文件哈希、残留进程和临时文件成为硬门禁。
- 所有报告只接受当前源码指纹、当前路径和当前二进制哈希。

退出条件：聚合器自身测试通过；旧报告、缺失报告、预算超限和指纹不一致均能可靠阻断发布。

### B. 六类 UI 研究与参考锁

- PDF：Adobe Acrobat + PDF24/PDFgear。
- 图片：XnConvert + Squoosh。
- 媒体：HandBrake + Shutter Encoder。
- 文件：PowerRename + Advanced Renamer。
- Office：Microsoft Office + LibreOffice。
- 文本：VS Code + Notepad++。

每类至少采集空状态、已配置、校验失败、运行中、成功、部分失败 6 种真实操作界面。保存原图、来源、日期、尺寸和版本；随后制作标注图、参考锁和决策账本。

退出条件：至少 36 张竞品原图、36 张标注图，六类决策账本完整，无宣传图冒充操作界面。

### C. 完整产品 UI 实现

- 保留沉浸式独立页面，不恢复主要流程弹窗。
- 按六类任务模型实现分类工作区，不能继续使用单一万能表单。
- 实现真实输入摘要、视觉预览、执行前冲突/损失检查、队列、逐项状态、真实阶段进度、取消、部分失败和失败项重试。
- PDF 提供页面范围/缩略图模型；图片提供前后预览；文件改名提供新旧名称；媒体提供源流/目标摘要；Office 提供页/表/幻灯片作用范围；文本提供命中与编码预览。
- 所有状态使用真实样本，不以静态模拟状态作为最终证据。

退出条件：六类代表功能完成真实交互；全部 114 个工具正确映射到分类模型；无阻塞弹窗；无假进度和假 ETA。

### D. UI 截图验收

- 生成竞品原图、标注图、本项目同状态图三栏对照。
- 本项目截图覆盖 `1200x760`、`1366x768`、`1920x1080`，Windows 100%/125% 缩放。
- 覆盖空、配置、错误、运行、成功、部分失败、取消、1000 项批量。
- 自动检查溢出、遮挡、不可达控件、空白画布和视觉回归。

退出条件：截图矩阵完整；所有自动检查通过；人工对照记录无未关闭 P0/P1。

### E. 后端进度、资源与正确性基础设施

- 处理引擎提供机器可读进度事件：阶段、当前项、总项、百分比、速度、ETA 可用性。
- 任务管理器记录整个进程树 CPU、RSS、IO、临时空间、退出原因和取消延迟。
- 文本、文件、图片、Office、PDF、媒体分别使用语义判定器，不能只检查存在、非空或可解码。
- 高风险格式至少两个独立判定器；Office 必须包含原生应用打开/保存证据。
- 预算超限必须失败，不能只记录指标。

退出条件：测试框架自测覆盖预算失败、超时、取消、部分输出、错误成功、指纹不一致和报告缺失。

### F. L0-L4 全矩阵执行与修复

- L0：114 个工具基础正确性。
- L1：真实负载及至少 10 次重复，输出语义一致。
- L2：1000 文件、500 页、4K/10 分钟媒体等大负载。
- L3：114 个工具全部执行实际极限，而非只测输入门禁。
- L4：畸形输入、只读/无权限、磁盘空间不足、依赖终止、进程强退、取消、并发冲突、临时目录故障、离线网络。

退出条件：P0/P1 为 0；所有强制用例 PASS；预算超限已优化、限制或降级并重新验证。

### G. L5 长稳与可用性

- 连续运行至少 24 小时且不少于 500 个任务。
- 100 次启动/退出；100 次成功/失败/取消混合循环。
- 每轮检查内存基线、句柄、子进程、文件锁、临时目录、源文件哈希。
- 5 名真正首次使用者在无文档、无开发者提示下完成六类核心任务；保存屏幕录制、耗时、错误和访谈记录。

退出条件：内存增长不超过 `100 MB` 或 `5%` 的更严格值；无残留；首次用户成功率不低于 90%。真人可用性测试不能由自动脚本或模型模拟替代。

### H. 安装、升级与发布

- 在干净 Windows VM 和 8 GB 低配实体机执行安装、离线运行、旧版升级、卸载和残留检查。
- 安装包内版本、界面版本、报告版本、源码指纹和二进制哈希一致。
- 安装版重跑代表性 L0-L4、画布、UI 截图和真实任务。
- 全部门禁通过后才提升版本号、构建最终安装包并计算 SHA-256。

退出条件：最终聚合报告为 `ACCEPTED`；任何缺失证据保持 `NOT_ACCEPTED`。

## 4. 失败修复规则

1. 正确性失败优先修复算法，不通过降低输入规模掩盖。
2. 性能失败优先流式处理、限制复制、控制并发和临时空间；确有产品边界时必须在前后端同时阻断并明确告知用户。
3. 取消和超时失败必须终止完整进程树并清理半成品。
4. UI 失败按竞品证据和参考锁修改，不凭主观偏好放行。
5. 修复后重跑该工具全部 L0-L5、同类别回归和安装版代表用例。
6. 每次失败保留原始报告，不覆盖失败证据；新报告使用独立 run ID。
