# 0.5.0 魔鬼压力测试与 UI 参考原型验收方案

> 文档性质：测试、调研、原型和发布门禁设计，不代表已经执行或通过。  
> 基线版本：0.5.0  
> 基线范围：114 个本地工具、主程序、画布、安装/升级/卸载链路。  
> 核心原则：没有可复现证据就不算通过；不能因“能生成文件”而判定用户可用。

## 1. 目标与非目标

本方案同时建立两条互不替代的验收线：

1. UI 参考原型验收：必须先调研成熟同类产品并保存截图，逐图拆解后再实现本项目原型，最终用本项目截图对照验收。
2. 后端魔鬼压力验收：对正确性、极限规模、异常输入、资源耗尽、并发、取消、恢复和长时间运行进行破坏性验证。

本方案不是简单冒烟测试，也不是只检查输出文件是否存在。以下行为禁止作为通过依据：

- 只用 1 个小样本验证工具。
- 只检查退出码、文件存在或文件非空。
- 只在开发机上运行，不保留输入、日志、指标和输出证据。
- 用历史报告替代当前版本复测。
- UI 只凭主观描述通过，不提供竞品截图和本项目截图。
- 某工具超时、卡死、无法取消时仍保留为稳定功能。

## 3. UI 竞品调研基线

### 3.1 强制调研对象

不能用一个产品覆盖所有类别。每个类别至少研究 2 个成熟产品，以一个为主参考，另一个只补充特定交互。

| 类别 | 主参考 | 次参考 | 必须截图的界面 | 本项目重点借鉴 |
|---|---|---|---|---|
| PDF | Adobe Acrobat Organize Pages | PDF24 Creator / PDFgear | 页面缩略图、页码范围、重排、压缩选项、结果页 | 页面级预览、范围反馈、结构损失警告 |
| 图片 | XnConvert | Squoosh | 输入列表、动作流水线、格式/质量、前后对比、预计大小 | 批量队列、比例锁、即时预览、大小变化 |
| 视频/音频 | HandBrake | Shutter Encoder | 源信息、预设、编码设置、队列、进度、ETA、取消 | 源/目标摘要、兼容性提示、队列与真实进度 |
| 批量改名/文件 | Microsoft PowerRename | Advanced Renamer | 原名/新名预览、规则、冲突、排除项 | 实时双栏预览、冲突阻断、可撤销说明 |
| Office | Word / Excel / PowerPoint 原生界面 | LibreOffice | 页/表/幻灯片范围、对象选择、导出、保存副本 | 原生对象心智模型、作用范围、保留原文件 |
| 文本处理 | VS Code Search/Replace | Notepad++ | 查找替换预览、正则错误、结果数量、逐项确认 | 命中预览、正则校验、编码和换行可见化 |

首轮来源必须优先使用官方产品页或官方文档：

- Adobe Acrobat：https://www.adobe.com/acrobat/online/rearrange-pdf.html
- PDF24：https://tools.pdf24.org/en/creator
- XnConvert：https://www.xnview.com/en/xnconvert/
- Squoosh：https://squoosh.app/
- HandBrake：https://handbrake.fr/docs/en/latest/introduction/quick-start.html
- Shutter Encoder：https://www.shutterencoder.com/
- PowerRename：https://learn.microsoft.com/windows/powertoys/powerrename
- Advanced Renamer：https://www.advancedrenamer.com/

- VS Code：https://code.visualstudio.com/docs/editing/codebasics
- Notepad++：https://npp-user-manual.org/docs/searching/

### 3.2 竞品截图取证规则

每张截图必须是实际界面，不得只截宣传海报、Logo 或功能文案。截图文件名统一为：

```text
<category>-<product>-<flow-step>-<state>-<yyyyMMdd>.png
```

每张原图必须同时记录：来源 URL、产品版本或访问日期、操作步骤、截图尺寸、DPI、页面状态、可借鉴点、不可照搬点。原图只用于内部设计研究，不冒充本项目成果。

每个类别至少保存以下证据：

1. 空状态或导入入口。
2. 已选择真实文件的配置状态。
3. 参数错误或不兼容状态。
4. 处理中状态，包括进度、速度、预计时间和取消。
5. 成功结果以及打开文件/目录入口。
6. 批量任务或部分失败状态。

### 3.3 逐图拆解与参考锁

每张竞品截图复制一份标注图，使用编号框标明：信息层级、主要操作、文件摘要、预览区、参数分组、危险操作、进度区、错误恢复和结果出口。

随后为每个类别建立参考锁：

| 决策 | 主参考证据 | 次参考证据 | 本项目实现 | 不采用原因 |
|---|---|---|---|---|
| 页面结构 | 截图文件名 + 标注编号 | 截图文件名 + 标注编号 | 对应原型区域 | 无关/复杂/版权/不适用 |
| 参数组织 | 同上 | 同上 | 控件和默认值 | 同上 |
| 预览方式 | 同上 | 同上 | 预览内容和刷新时机 | 同上 |
| 运行反馈 | 同上 | 同上 | 进度、ETA、取消 | 同上 |
| 结果反馈 | 同上 | 同上 | 成功、部分失败、重试 | 同上 |

不得照抄单一竞品的品牌、图标、文案和视觉资产。参考的是经过验证的信息架构和交互模式，本项目继续保持沉浸式独立页面，不恢复阻塞式弹窗。

## 4. UI 原型实现与截图验收

### 4.1 原型顺序

1. 先完成竞品原图和标注图。
2. 为 PDF、图片、媒体、文件、Office、文本分别制作低保真结构原型。
3. 评审参考锁，确认每个关键区域有来源。
4. 实现本项目可交互原型。
5. 使用真实文件进入每一种关键状态。
6. 生成本项目截图和竞品对照图。
7. 原型验收后才能批量推广到同类工具。

优先选择每类 1 至 3 个高价值工具做完整原型，禁止直接把未经验证的万能参数表单复制到 114 个入口。

### 4.2 每个工具必须具备的状态

- 空状态：未选择文件，主要操作明确。
- 已配置：文件、输出位置、关键参数和预计影响可扫描。
- 校验失败：字段旁说明具体原因和修复方法。
- 运行中：真实进度、已用时间、预计剩余、当前文件、取消按钮。
- 部分失败：成功和失败文件分别列出，可重试失败项。
- 已取消：说明已清理内容，不能显示为执行失败或成功。
- 成功：输出数量、路径、大小变化、打开文件和打开目录。
- 极端批量：1000 项时界面仍能滚动、筛选和响应，不能渲染冻结。

### 4.3 截图规格

所有关键状态至少在以下环境截图：

- `1200 x 760`：当前主窗口和画布默认尺寸，强制基线。
- `1366 x 768`：常见低分辨率 Windows 笔记本。
- `1920 x 1080`：常见桌面屏幕。
- Windows 缩放 `100%` 和 `125%`。
- 中文长文件名、超长路径、1000 个文件、最长参数文案。

截图不得使用空白演示数据。文件名、页数、分辨率、时长、大小、错误原因和输出路径必须来自实际测试样本。

### 4.4 UI 对照验收

每个原型生成一张三栏对照图：

```text
[竞品原始截图] [竞品标注截图] [本项目同状态截图]
```

人工验收逐项确认：任务入口是否清楚、主要操作是否唯一、参数是否按用户目标组织、默认值是否安全、结果是否可发现、错误能否恢复、长内容是否溢出、运行状态是否可信、取消是否随时可达。

原型批准后建立本项目视觉基线。后续版本对基线截图执行自动视觉回归；核心区域像素差异超过 `0.5%` 或布局框差异超过 `4px` 时必须人工复核。竞品图只用于设计对照，不参与像素级比较。

### 4.5 UI 否决条件

出现以下任一项即为不通过：

- 长任务没有真实进度或取消。
- 仍用阻塞式对话框承载主要工作流。
- 参数名称是底层命令术语，普通用户无法判断结果。
- 图片裁剪、水印、PDF 页面操作等视觉任务没有预览。
- 批量改名没有执行前的新旧名称预览和冲突检查。
- 媒体转码没有源信息、目标摘要、ETA 或编码兼容提示。
- 错误只显示“失败”“异常”或原始堆栈，没有原因和处理建议。
- 默认参数可能覆盖原文件、丢失透明通道、文本层、链接、书签或媒体轨道，却没有醒目提示。
- `1200 x 760`、`1366 x 768` 或 125% 缩放下出现遮挡、溢出、按钮不可达。

## 5. 后端魔鬼压力等级

普通正确性样本只算 L0，不计入魔鬼压力通过率。

| 等级 | 名称 | 目的 | 示例 |
|---|---|---|---|
| L0 | 基线 | 确认工具可启动 | 1 个小文件 |
| L1 | 真实负载 | 覆盖常见用户任务 | 10 至 100 个真实文件 |
| L2 | 大负载 | 验证吞吐和资源曲线 | 1000 文件、500 页、4K 媒体 |
| L3 | 极限负载 | 逼近产品声明边界 | 10 万文件、5000 页、16K 图片、超长媒体 |
| L4 | 破坏负载 | 验证异常和恢复 | 损坏文件、磁盘满、权限丢失、依赖进程崩溃 |
| L5 | 长稳负载 | 验证泄漏、锁和残留 | 24 小时循环、连续取消和重启 |

稳定工具必须通过 L0 至 L5。无法合理执行 L3 的工具必须在 catalog 中声明硬限制，并在输入阶段阻断，不能等到处理中崩溃。

## 6. 全工具通用魔鬼矩阵

### 6.1 输入与路径

- 空文件、零字节、错误扩展名、伪造文件头、截断文件、随机字节。
- 中文、日文、阿拉伯文、Emoji、组合字符、保留字符附近命名。
- 260 字符以上路径、深层目录、同名文件、大小写冲突。
- 只读文件、只读目录、无权限目录、网络盘、断开的移动盘。
- 输入和输出相同、输出位于输入子目录、符号链接或目录循环。
- 批处理中途删除、改名或锁定输入文件。

### 6.2 资源耗尽与故障注入

- 输出盘仅剩 `1 GB`、`100 MB`、`1 MB` 和完全写满。
- 8 GB 低配机并限制可用内存，观察是否出现 OOM 或系统失去响应。
- 后端、FFmpeg、Python、pdfcpu、ExifTool 子进程在 10%、50%、90% 进度被终止。
- 处理中取消、连续点击取消、取消后立即重新运行。
- 主程序强退、系统重启、注销、休眠和唤醒。
- 临时目录不可写、临时目录被清理、杀毒软件短暂锁定输出。
- 外部依赖缺失、版本不兼容、环境变量污染、离线网络。

### 6.3 并发与队列

- 同一工具同时提交 1、2、4、8 个任务。
- 图片、PDF、Office、媒体混合排队。
- 重复输入同一文件，输出命名发生竞争。
- 队列运行时新增、取消、重排任务。
- 1000 次快速点击执行不能生成 1000 个失控子进程。
- UI 关闭后不得遗留不可见的后台任务，除非用户明确选择后台继续。

### 6.4 长稳

- 24 小时连续循环，至少 500 个任务。
- 100 次启动/退出，检查句柄、临时目录和进程残留。
- 100 次成功、失败、取消混合循环。
- 每轮记录空闲内存基线；累计增长超过 `100 MB` 或 `5%` 判为疑似泄漏。
- 每轮结束检查原文件哈希、输出可读性、临时文件和文件锁。

## 7. 分类魔鬼场景

### 7.1 文本与文件

- 1 GB 单文本、1000 万行、单行 100 MB、无末尾换行。
- UTF-8、UTF-8 BOM、UTF-16LE/BE、GB18030、混合乱码和非法字节。
- 10 万文件分类或改名，包含同名冲突和编号溢出。
- 正则空匹配、超大捕获结果、非法表达式和替换膨胀。
- 操作前后逐文件哈希核对，禁止误改原文件或漏文件。

### 7.2 图片

- 1、100、1000 张混合格式图片。
- 8K、16K、超宽、超高、1 像素、损坏帧、动画 GIF/WebP。
- 解压炸弹、巨量像素但压缩体积极小的恶意图片。
- Alpha、ICC、EXIF 方向、DPI、多页 TIFF、CMYK JPEG。
- 检查像素尺寸、透明通道、帧数、色彩配置、元数据和输出大小。

### 7.3 Office

- 500 MB DOCX/XLSX/PPTX、1000 页文档、1000 工作表、5000 幻灯片。
- 大量嵌入图片、重复关系、外部链接、批注、图表、母版和主题资源。
- 加密文件、损坏 ZIP、ZIP 炸弹、缺失关系目标、宏文件和旧格式文件。
- 使用 Word、Excel、PowerPoint 原生打开，并校验页/表/幻灯片数、关系完整性和媒体哈希。
- 任何“能解压但原生 Office 修复后才能打开”的输出均不算通过。

### 7.4 PDF

- 1、100、1000、5000 页；纯文本、扫描件、混合页尺寸和旋转页。
- 加密、错误密码、损坏 xref、增量更新、多重对象流、超大内嵌图。
- 表单、批注、签名、附件、书签、链接、透明层和字体子集。
- 压缩后同时校验体积、可搜索文本、链接、书签、表单和视觉差异。
- 栅格化模式必须明确判定结构损失，不能与无损压缩混为一类。

### 7.5 视频与音频

- 4K/8K、HDR、VFR、10-bit、旋转元数据、超宽视频和超长音频。
- 多音轨、多字幕、封面、章节、不同采样率、异常时间戳。
- 截断媒体、损坏关键帧、音画不同步、零时长流、无音频或无视频流。
- 连续转码 24 小时；过程中取消、强退和磁盘写满。
- 使用 ffprobe 校验容器、编码、时长、分辨率、帧率、轨道、时间基和音画同步。
- 网页下载必须测试限速、断网、重连、重定向、超大文件和站点拒绝，不测试绕过 DRM 或访问控制。

## 8. 性能与可用性硬门槛

首轮采用以下门槛，完成基线测量后只能收紧；放宽必须写明证据和批准人。

| 指标 | 门槛 |
|---|---|
| UI 操作反馈 | 300 ms 内出现状态变化 |
| 任务进度 | 任务开始后 1 s 内出现，之后至少每 1 s 更新 |
| 取消延迟 | 2 s 内终止整个进程树 |
| 无响应 | 主窗口连续 2 s 无响应即记录失败 |
| 空闲总 RSS | 500 MB 以内 |
| 普通任务峰值 RSS | 1.5 GB 以内 |
| 重型任务峰值 RSS | 16 GB 机器不超过 4 GB；8 GB 机器不超过 2.5 GB |
| 长稳内存增长 | 100 MB 或 5% 以内，取更严格值 |
| 取消后残留 | 无子进程、无文件锁、无不可解释临时文件 |
| 原文件保护 | SHA-256 必须完全一致，除非工具明确声明原地修改并二次确认 |
| 静默失败 | 0；不允许返回成功但输出缺失或损坏 |
| 超时 | 所有任务必须有分类超时，禁止无限等待 |

速度不能只给统一秒数。文本/改名使用文件数和字节吞吐；图片使用百万像素每秒；PDF 使用页每秒；Office 使用对象数/媒体数和文档规模；媒体使用处理帧率与实时倍速。每项保存冷启动、热启动、p50、p95 和最坏值。

## 9. 正确性判定器

每种输出必须使用结构化判定器，不得只用文件存在和文件大小：

- 文本：编码、换行、行数、内容哈希、替换命中数。
- 文件：输入输出映射、数量、名称冲突、逐文件哈希。
- 图片：magic number、解码、尺寸、帧数、Alpha、ICC、EXIF、像素差异。
- Office：ZIP/OOXML 关系、内容类型、媒体引用、原生 Office 打开和保存。
- PDF：解析器交叉验证、页数、文本、书签、链接、表单、字体和渲染图差异。
- 媒体：ffprobe 流信息、时长、时间基、分辨率、帧率、音轨、字幕和同步。

高风险格式至少使用两个独立判定器。例如 PDF 同时用 pdfcpu/pypdf 和页面渲染；Office 同时检查 OOXML 结构并用原生 Office 打开。

## 10. 自动化实施设计

后续实现阶段新增：

```text
verify/devil/
  manifest.json        # 114 工具、负载等级、预算、判定器、超时
  runner/              # 任务运行、进程树终止、资源采样、故障注入
  generators/          # 可重复的大样本和畸形样本生成器
  oracles/             # 分类正确性判定器
  report/              # JSON 与 HTML 报告生成
```

`backend/tool_catalog.json` 增加但不限于以下发布元数据：

```json
{
  "maturity": "stable | experimental | hidden",
  "limits": {},
  "timeoutSeconds": 0,
  "performanceBudget": {},
  "uiReferenceId": "",
  "acceptanceCaseIds": []
}
```

运行器必须支持：固定随机种子、单用例重跑、超时、完整进程树终止、CPU/RSS/IO 采样、磁盘空间采样、取消注入、退出码归一化、日志脱敏、输入输出哈希、失败样本保留和 HTML 汇总。

## 11. 工具分级与发布门禁

| 状态 | 条件 | 产品行为 |
|---|---|---|
| stable | L0-L5、正确性、性能、UI 和安装验收全部通过 | 默认展示 |
| experimental | 正确但部分极限或 UI 未通过 | 单独实验区并明确风险 |
| hidden | 卡死、错误输出、无法取消、无可信进度或用户无法完成 | 正式界面隐藏 |
| removed | 重复、价值不足、不可维护或风险不可控 | 删除入口和实现 |

最终发布必须同时满足：

- 所有 114 个工具都有完整矩阵记录，不允许“未测即通过”。
- stable 工具的强制用例通过率 100%。
- P0/P1 为 0；P2 必须有明确修复版本或降级为 experimental/hidden。
- 24 小时长稳通过，无持续内存增长、残留进程、文件锁和临时垃圾。
- UI 六大类别均有竞品原图、标注图、决策账本、本项目原型图和最终截图。
- 5 名首次使用者完成核心任务成功率不低于 90%，期间不得依赖说明文档或开发人员提示。
- 干净 Windows 虚拟机和低配置实体机完成安装、离线运行、旧版升级、卸载和残留检查。
- 安装包内版本号、应用显示版本、报告版本和 SHA-256 一致。

## 12. 严重级别与立即停止条件

- P0：损坏原文件、静默错误输出、系统级崩溃、无法停止的大量子进程、安全越界。立即停止发布。
- P1：常见输入失败、界面长时间冻结、取消无效、结果不可打开、错误状态显示成功。修复前不得稳定发布。
- P2：极端场景失败、明显性能退化、部分格式信息丢失但有明确提示。必须修复或降级。
- P3：文案、轻微布局或非关键视觉差异。可排期，但必须留证据。

任一测试出现原文件哈希变化、输出目录越界、进程失控、系统磁盘写满后仍继续写入、同一失败连续三次不可复现定位时，立即停止当前批次，保全样本、日志、转储和环境快照。

## 13. 推荐执行顺序

1. 冻结版本和 114 工具清单，修复验收脚本在干净目录不可运行的问题。
2. 完成六类竞品 UI 截图、标注图和参考锁。
3. 实现六类代表工具原型并完成截图验收。
4. 实现统一进度、取消、超时、队列和进程树治理。
5. 建立魔鬼测试 manifest、样本生成器、资源采样和正确性判定器。
6. 先执行 L0-L2，修复基础正确性和可观测性。
7. 再执行 L3-L5，处理资源边界、故障恢复和长稳问题。
8. 按 stable/experimental/hidden/removed 重新整理 catalog。
9. 在干净机完成 UI 截图复验和安装包验收。
10. 只有全部门禁满足后才提升版本号并生成新安装包。

此顺序禁止反转。没有进度、取消、超时和结构化判定器时直接跑极限压力，只会得到“很慢或卡死”，无法形成可定位、可复现的工程证据。
